# BETTER_AUTH_URL is set for Production only, left unset on Preview

`BETTER_AUTH_SECRET` and `BETTER_AUTH_URL` were missing from Vercel for every environment (issue #35), which is fatal for `BETTER_AUTH_SECRET`: Better Auth refuses to start with its built-in default secret whenever `NODE_ENV=production`, and Vercel sets `NODE_ENV=production` for both Production **and** Preview builds — so every deployed environment threw on the first `/api/auth/*` request (`src/lib/auth-secret-guard.test.ts` reproduces this). `BETTER_AUTH_SECRET` is now set for Production and Preview alike, generated once and pushed to both.

`BETTER_AUTH_URL` is different: it's the app's canonical base URL, used for callback/redirect correctness, and it's only fatal-adjacent (a logged warning, not a thrown error) when unset. Production has exactly one stable domain, so it gets a fixed `BETTER_AUTH_URL`. Preview does not — Vercel gives every branch and every deployment its own URL, and this repo has no single Preview alias that would stay correct across feature branches. Pinning `BETTER_AUTH_URL` to one Preview URL would silently mis-set the origin on every other branch's preview.

Confirmed and fixed as the current, working state during a Better Auth secret diagnosis session (2026-09-07, issue #35). Decided: leave `BETTER_AUTH_URL` unset on Preview and accept Better Auth's documented fallback — deriving the origin from each incoming request — over either of the two alternatives considered: pinning it to one branch's alias (breaks other branches' previews) or configuring `baseURL` as a dynamic host allow-list (`betterAuth({ baseURL: { allowedHosts } })`) to explicitly trust `*.vercel.app`, which is more precise but is a `src/lib/auth.ts` code change, not just an environment-variable fix, and was out of scope for this pass. `scripts/supabase-setup.sh`'s Better Auth stage documents this out loud when it runs.
